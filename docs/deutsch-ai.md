The app proxies AI requests through authenticated `/api/deutsch-ai/*` routes to `https://vixoaidanloi.com/api/deutsch-ai/*`. Requests time out after 60 seconds and are not cached.

Gap exercises use the separate `/qwen` endpoint through `/api/deutsch-ai/exercises`. Set `AI_SERVICE_TOKEN` to the service's Bearer token on the server. The request sends `{prompt, context}` and times out after 5 seconds. No token is sent to the browser. Article and translation exercises use saved flashcards directly, so they do not wait for AI.

On `/exercises`, click one of the three exercise cards and choose a topic in the popup. The server loads up to five selected cards owned by the signed-in user. For gap exercises it asks the AI service for short German examples and Vietnamese translations in structured JSON. The popup shows a loading state while the service responds. If the service is slow, unavailable, or returns unusable content, the server creates gap questions from saved examples; cards without examples receive a simple vocabulary sentence. The fallback is disclosed in the exercise view. It accepts direct JSON or JSON text in common response envelopes (`response`, `text`, `output`, `content`, `answer`, or OpenAI-style `choices`). The actual response envelope still requires verification with a configured service token.

Gap questions blank an exact whole-word occurrence in the generated sentence. Article and vocabulary translation questions keep the saved card's reference answers and reveal the new example and explanation after submission. AI answers cannot overwrite these reference answers. Invalid or incomplete batches show an error and can be regenerated. AI rounds use the existing result history and first-answer scoring; reviewing mistakes reuses the generated questions. Generation can be cancelled and is aborted when filters change or the component unmounts.

The upstream returned HTTP 401 for an unauthenticated sample request during integration. If the service uses Bearer authentication, set `AI_SERVICE_TOKEN` on the Next.js server. Never use a `NEXT_PUBLIC_` variable for this credential. Confirm the service's authentication scheme and response fields before production use.

The new-flashcard form can generate an example before saving the card. The browser sends `{word, meaning_vi}`; the server supplies A1 to the upstream service. Generated text fills the example and translation fields, which can be edited before saving. The response adapter accepts `example_de`/`example_vi`, `sentence_de`/`translation_vi`, `sentence_de`/`sentence_vi`, or `example`/`translation` (also `german`/`vietnamese`) and requires both sentences. Update `lib/ai-results.ts` if the service uses another response schema.

Flashcard listening asks the browser to speak with `de-DE` and lets it choose its default voice. It does not call the AI service.

Run `npm run db:migrate` before deploying the pronunciation scoring feature. This adds the nullable `flashcards.ipa` column without replacing existing data. Enter the reference IPA (for example `/tyːɐ/`) when adding or editing a flashcard. Existing cards without IPA show instructions instead of enabling scoring. This integration does not invent IPA.

Recording requires HTTPS (or localhost), microphone permission and MediaRecorder. Recording stops after 15 seconds; uploads are limited to 5 MB. The browser sends its supported WebM/Opus, MP4 or Ogg recording. Verify these input formats with the scoring service. The server looks up `expected_ipa` by authenticated owner and card ID, and forwards multipart `audio` and `expected_ipa`. The score adapter accepts `{score: number}` or `{ipa_similarity: number}` on a 0–100 scale; it rejects out-of-range values rather than inventing or rescaling scores. After scoring, the speaker button replays the learner's original recording from a temporary browser object URL. The recording is released when a new attempt starts or the card is closed. Reference IPA and recordings are not persisted by this app beyond the flashcard's IPA field.

To check the learner recording flow, add IPA to a card, open that card under `/flashcards/study`, open the microphone icon, allow microphone access, press “Ghi âm phát âm”, speak, and press “Dừng và chấm điểm”. The button is disabled for cards without IPA. Once the score appears, use the speaker icon to replay the recording. The browser test in `e2e/pronunciation.spec.ts` simulates microphone capture and verifies the audio upload, displayed score and replay control. A live score also requires a configured database, `AI_SERVICE_TOKEN`, and a scoring service that accepts the browser's recording format; those external dependencies are separate from the simulated browser check.
